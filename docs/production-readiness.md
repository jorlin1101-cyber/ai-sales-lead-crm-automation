# 实际业务使用边界与后续路线

## 当前已经具备

2026-09-05 的新增实现与验证记录见 [逐项复核表](workflow-implementation-review.md)。
已经增加多轮持久化、失败恢复、版本审核、隔离访客和 CRM 结果核对；这些不等于已完成生产部署认证。

- 线索清洗、格式校验、规则评分、来源展示与人工确认相互分离；
- 同一外部线索生成稳定编号，Notion 写入前查询已有记录；
- 邮件草稿可人工编辑，CRM 保存人工确认稿；
- 垃圾推广和安全风险线索不自动生成邮件；
- Notion 限流按 `Retry-After` 处理，非幂等创建请求不会盲目重放；
- 页面不依赖第三方字体服务，离线演示不会额外请求字体域名。

## 上线前仍然必须完成

1. **身份与权限**：已有本地操作员、令牌保护和隔离离线访客模式，审计身份来自服务端。
   正式团队仍需企业登录、细粒度角色权限和网关级共享限流；当前访客配额为进程内配额。
2. **数据生命周期**：明确线索来源、处理目的、保存期限、删除和导出流程，生产日志不得记录
   邮箱、电话或完整客户留言。
3. **渠道合规**：邮件发送系统需要退订机制、抑制名单和频率控制。本项目目前只生成草稿，
   不会自动发送邮件。
4. **策略校准**：`PolicyV1` 面向定制旅行 B2B 获客排序，不能直接迁移为通用客户价值评分。
   上线前需用历史转化数据按渠道、客户类型和语言分层评估阈值与误差。
5. **可靠存储**：已有 PostgreSQL 兼容存储、唯一约束、恢复租约与持久化同步任务记录。
   生产 PostgreSQL 实机迁移、负载测试、备份恢复、后台队列与人工异常处理仍需验收。

## 为什么加入这些边界

《个人信息保护法》第六条要求处理目的明确、采取对个人权益影响最小的方式并限制在最小范围；
第二十四条要求自动化决策保持透明、公平、公正，并为商业营销提供便捷拒绝方式。项目因此保留
评分拆解、适用范围提示、人工确认和来源合法性确认，但这些产品设计不能替代组织自身的合规
制度与法律评估。
