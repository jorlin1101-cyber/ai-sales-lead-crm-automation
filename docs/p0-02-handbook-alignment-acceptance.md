## 用产品功能解释本次变化

产品主流程没有重构。本次升级的是“判断系统有没有答对”的检查工具：把原产品手册已有的规则和人为构造的测试规则分开，为每个答案标出原文出处，分别统计结果，并给每轮实际回复配上中文复核说明。

具体新增了来源追踪、分组统计、旧新版本隔离、完整回复复核材料；修改了24个测试场景及其判定标准、报告和可信接纳检查。没有把机场接送、固定导游工时、促销等新增政策写入原产品手册。当前已知的人数更正问题仍存在，后续需要单独修复产品代码。

本轮按 [手册对齐计划](p0-02-handbook-alignment-plan.md) 实施 `p0-02.v2`，对新增案例的业务确认与实际回复审核分别保留待完成状态。

## 业务结果与保留的问题

两种模式各有180项检查：**70项自动通过、2项失败、108项待复核**。每模式36轮的回答语义均有待复核内容；没有将待复核算成失败率或准确率。已生成 [真实审核草稿](../data/runtime/p002-v2-development/review-draft-final.json)：216个待裁定检查各需开发与业务角色审核，共432条空白记录；身份、结论和批准信息均未虚构。

人数更正失败发生于AB22的T2/T3，两模式均保留。另以旧版原始输入逐字复测，实际人数仍为 **8→8→8**，应为 **8→9→9**；来源仍停留在T1，与旧封存结果一致。[原输入诊断](../data/runtime/p002-v2-development/legacy-ab22-final/summary.md) 只作诊断，不计入v2成绩，未借换题宣称修复。

原手册可答问题的独立检索中，原问题路径与融合路径的要点召回均为13/13，规则改写路径为7/13。这表明规则改写后仍有检索遗漏，不能解释为手册没有答案；13是适用的可答要点数，不是全部场景数。这些离线检索数值也不代表最终回复正确。

付款的“抵达前14天”与“出发前14天”两种说法均保留，定金30%仍单独可答；儿童优惠的年龄和与父母同住条件保留，具体金额仍未知。原取消条款保持完整，专项人为退款冲突独立隔离；本版原手册组没有专门的退款问句，因此不能声称原退款回复已实测正确。

本轮修复了检查工具的实际缺口：分组汇总缺项或缩小分母可被拒绝；基线登记不一致不能退回较弱检查；从仓库外执行也能找到原基线。另修正v2模拟模型把FAQ标题/问题当回复、导致生产校验拒绝的问题：只从实际给到的资料中选陈述句，仍不读取标准答案，v1策略不变。

## 运行方法

下列命令默认使用v2；每次更换为全新输出目录，封存目录不可覆盖。

```powershell
.venv\Scripts\python.exe scripts/run_answerability_eval.py run --mode rule_only --out data/runtime/p002-v2-example/rule_only
.venv\Scripts\python.exe scripts/run_answerability_eval.py run --mode mocked_model --out data/runtime/p002-v2-example/mocked_model
```
